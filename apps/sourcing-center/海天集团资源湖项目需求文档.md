# 海天集团供应链资源湖（SCROS）项目需求文档

资料来源：`assets/海天集团资源湖项目（AI 赋能）.pdf`

适用范围：本需求文档用于海天集团供应链资源湖（SCROS, Supply Chain Resource Operating System）项目的立项、方案细化、产品规划、实施拆解与跨部门沟通。

## 1. 项目背景

### 1.1 社会现状与行业趋势

当前制造业供应链正在从稳定、线性、低波动的传统模式，进入高不确定性、高波动性、强协同要求的新阶段。企业采购和供应链管理面临的外部环境已经发生明显变化：

1. 全球供应链进入重构周期
   过去以“成本最优”为核心的全球化供应链模式，正在转向区域化、近岸化、多区域、多供应商的供应网络。企业需要建立更加分散、灵活、可替代的供应体系，以降低单一区域、单一供应商、单一渠道带来的系统性风险。

2. 地缘政治和贸易环境不确定性增强
   地区冲突、贸易制裁、关税壁垒、国际物流受阻等因素逐渐常态化。传统依赖固定供应商和线下经验判断的采购模式，难以及时识别断供、价格异常和合规风险。

3. 原材料价格和市场供需波动加剧
   大宗商品、关键零部件、核心材料价格波动频繁，传统议价和成本核算模式难以及时反映市场变化。企业需要通过数据和模型建立敏捷的成本传导和价格评估能力。

4. AI 正在重构供应链效率
   人工智能、大数据、智能体（AI Agent）正在从信息辅助工具，升级为供应链业务决策的重要能力。领先企业已经开始利用 AI 做需求预测、供应商匹配、库存优化、风险预警和自动化决策。

5. 世界一流企业已形成供应链操作系统能力
   华为、美的、三一、海尔等领先企业的实践表明，供应链竞争不再只是采购执行效率的竞争，而是端到端流程集成、全球协同、主动设计供应网络、数据驱动决策和生态协同能力的竞争。

### 1.2 海天当前面临的问题

结合 PDF 中对外部环境和内部挑战的分析，海天集团当前供应链管理主要存在以下问题：

1. 供应商资源分散，集团级复用不足
   各产业、各生产基地的供应商资源存在割裂现象，供应商信息、采购价格、质量、交付、产能、风险等数据分散在不同系统、部门和业务人员手中，缺少集团统一视图。

2. 重复寻源严重，采购效率受限
   不同业务单元可能针对类似物料重复寻找供应商，造成时间、人力和沟通成本浪费。优质供应商无法在集团范围内被充分共享和复用。

3. 决策依赖经验，缺少量化依据
   传统采购更多依赖采购员经验、历史合作印象和人工判断。供应商准入、价格判断、份额分配、风险识别等关键决策缺少统一、客观、可追溯的量化模型。

4. 供应风险预警能力不足
   对供应商财务、合规、舆情、地缘政治、战争疫情、关键原材料波动等风险缺乏系统化、实时化监控。风险发生后更多依赖事后应对，缺少提前预警和替代方案。

5. 供应链韧性不足，柔性替代能力不强
   对关键物料和关键供应商的替代梯队建设不足，一旦发生断供、交付延迟、质量波动或突发公共事件，供应链切换效率和响应速度受限。

6. 现有系统偏执行，缺少战略操作能力
   传统数据库和 SRM 系统更多解决信息记录、流程执行和供应商管理问题，但缺少主动发现价值、智能决策、资源统筹和生态协同能力。

### 1.3 建设 SCROS 的必要性

海天需要建设一个集团级、跨部门、可持续演进的供应链资源操作系统，将供应链从“经验驱动采购”升级为“数据驱动采购”，并进一步升级为“AI 驱动采购”。

SCROS 的核心定位不是单一采购工具，也不是现有 SRM 的简单升级，而是集团供应链的战略操作系统：

1. 对内，统一供应链资源、数据、模型、流程和决策能力。
2. 对外，连接优质供应商和产业资源，形成可协同、可扩展、可进化的供应链生态。
3. 对业务，提升寻源效率、降低采购成本、优化供应商份额、增强供应链韧性。
4. 对管理，推动供应链从“成本中心”转变为“价值创造中心”。

## 2. 项目目标

### 2.1 总体目标

建设海天集团供应链资源湖（SCROS），形成“一湖、两池、三平台、六大 AI Agent”的新一代供应链操作系统。

通过整合供应商、价格、质量、交付、产能、风险、工艺、行业与海外资源等全域数据，建立统一可信的数据底座；通过资源池和柔性供应池实现资源共享与敏捷替代；通过资源开发平台、数据治理平台和智能决策平台形成核心能力；通过 AI Agent 将寻源、核价、画像、份额、风险、调度等关键业务流程智能化。

### 2.2 要解决的核心问题

1. 解决资源分散问题
   建立集团统一供应商资源湖，形成唯一供应商 ID 和统一资源视图，打破产业、基地和部门之间的资源壁垒。

2. 解决重复寻源问题
   通过集团资源池和资源开发平台，实现优质供应商共享复用，减少重复寻源和重复认证。

3. 解决经验决策问题
   建立供应商 360 度画像、动态核价模型、动态份额模型和风险评估模型，使采购决策有数据、有模型、有依据。

4. 解决风险响应滞后问题
   建立风险识别、风险评估、风险应对和监控审查闭环，提升对单一来源、财务、地缘政治、战争疫情、关键原材料等风险的预警与处置能力。

5. 解决柔性供应不足问题
   建立关键物料的柔性供应池和动态备用梯队，在需求变化、供应异常或突发风险时快速切换供应资源。

6. 解决供应链生态协同不足问题
   面向核心战略供应商开放部分非敏感数据和协同功能，构建数据共享、风险共担、流程互通的供应链生态。

### 2.3 实现路径

项目采用分阶段建设路径：

1. 2026 年：资源湖 1.0 - 夯实基础，试点先行
   完成 SCROS 基础架构搭建，初步建立统一供应商资源池，在 C 类零件、通用品类开展试点。

2. 2027 年：资源湖 2.0 - 深化应用，构建能力
   完善八大核心数据库，上线供应商画像、核价模型和产能仪表盘，推动业务从经验驱动转向数据驱动。

3. 2028 年：SCROS 3.0 - AI 驱动，全面智能
   六大 AI Agent 全面上线，嵌入寻源、谈判、履约、份额分配、风险预警和调度等关键流程。

4. 2030 年：打造领先的供应链操作系统
   形成 AI 深度驱动、资源全球协同、供应链高韧性、管理透明可视的集团级供应链操作系统。

### 2.4 预期结果

1. 采购效率提升
   通过资源共享、智能寻源和流程优化，缩短寻源周期与沟通周期。

2. 采购成本降低
   通过核价模型、动态份额、市场化竞争机制和供应商资源复用，推动采购成本下降。

3. 库存成本优化
   通过资源调度、产能可视和供应链协同，降低安全库存和库存占用。

4. 供应链韧性增强
   通过柔性供应池、风险预警和替代供应商梯队，增强对断供、价格波动、交付异常等事件的应对能力。

5. 管理更加科学透明
   通过统一数据、统一模型和自动化评估报告，使采购决策过程可追溯、可审计、可优化。

6. 组织能力沉淀
   将采购经验、供应商评估逻辑、核价规则和风险处置策略沉淀为系统能力，减少对个人经验的依赖。

## 3. 项目需求

### 3.1 总体架构需求

SCROS 总体架构应围绕“一湖、两池、三平台、六大 AI Agent”展开。

#### 3.1.1 一湖：供应链资源湖

供应链资源湖是集团供应链的统一数据底座，需要汇聚、清洗、治理并持续更新供应链相关全域数据，形成统一、可信、可调用的数据资产。

核心数据范围包括：

1. 供应商基础信息
   包括供应商名称、统一社会信用代码、组织架构、联系人、地址、资质、认证、历史合作关系、所属产业链环节等。

2. 价格与询价数据
   包括历史采购价格、询价记录、报价记录、合同价格、价格变化趋势、原材料价格关联关系等。

3. 质量数据
   包括来料检验、生产过程质量、售后反馈、质量异常、质量整改、质量体系认证等。

4. 交付数据
   包括准时交付率、交付周期、订单履约率、延期记录、响应速度、售后服务响应等。

5. 产能数据
   包括产能规模、设备情况、设备利用率、扩产能力、可切换产线、产能瓶颈等。

6. 风险数据
   包括财务信用、法律涉诉、经营异常、合规风险、舆情风险、地区风险、政策风险等。

7. 工艺与技术数据
   包括标准工艺路线、关键工艺参数、技术规范、物料特征、生产难点、技术能力要求等。

8. 行业、市场与海外资源数据
   包括宏观经济、行业政策、产业集群、市场供需、技术发展趋势、海外供应商资源等。

#### 3.1.2 两池：统筹资源池与柔性供应池

1. 统筹资源池
   将集团内所有经过认证、可共享的供应商资源统一管理，形成“集团供应商超市”。资源池需要支持集团可见、分类管理、动态更新、跨产业和跨基地复用。

2. 柔性供应池
   在统筹资源池基础上，针对关键物料筛选出具备快速替代、快速切换和能力匹配的供应商子集，形成“动态备用梯队”。柔性供应池用于应对断供、质量异常、价格剧烈波动、需求突增等风险场景。

#### 3.1.3 三平台：能力构建核心引擎

1. 资源开发平台
   集成 AI 寻源、产业集群地图、供应商准入认证等能力，重构供应商开发和资源匹配流程。

2. 数据治理平台
   提供数据集成、清洗、标准化、主数据管理、质量监控和数据生命周期管理能力，保证 SCROS 数据可信可用。

3. 智能决策平台
   集成 AI Agent、优化算法、评分模型、核价模型、份额模型和风险模型，为供应链关键决策提供数据化、智能化建议。

#### 3.1.4 六大 AI Agent

六大 AI Agent 面向核心业务场景，包括：

1. 寻源 Agent
2. 核价 Agent
3. 画像 Agent
4. 份额 Agent
5. 风险 Agent
6. 调度 Agent

AI Agent 需要以资源湖数据为基础，以业务规则和模型为约束，以采购流程和供应链决策为落点，实现“数据输入 - 智能分析 - 策略输出 - 人工确认 - 结果回写”的闭环。

### 3.2 供应链资源湖需求

#### 3.2.1 建设目标

构建集团唯一可信的供应链数据源，使供应商全生命周期管理、智能寻源、动态核价、供应商画像、份额分配和风险预警都能基于统一数据底座开展。

#### 3.2.2 具体措施

1. 建立统一供应商主数据
   为供应商建立唯一供应商 ID，解决同一供应商在不同系统、不同基地、不同业务单元中重复、别名、口径不一致的问题。

2. 建立供应商数据标准
   制定供应商基础信息、资质、价格、质量、交付、产能、风险、工艺等数据标准，明确字段、格式、来源、责任人、更新频率和质量规则。

3. 开展历史数据清洗与标准化
   对现有供应商数据进行去重、补全、校验、纠错和统一编码，保证数据完整性和一致性。

4. 打通数据来源
   对接采购、质量、生产、财务、法务、计划、仓储、外部征信、市场行情、行业情报等数据来源，形成持续更新机制。

5. 建立数据质量监控
   对数据完整率、准确率、及时率、重复率、异常率进行监控，形成数据问题发现、派发、修复和复核闭环。

6. 支持数据资产沉淀和复用
   将价格曲线、供应商画像、质量档案、交付绩效、风险标签、产能能力、工艺路线等沉淀为可复用资产。

### 3.3 统筹资源池需求

#### 3.3.1 建设目标

建立集团统一供应商资源池，实现优质供应商的集团级共享、查询、调用、复用和评估，降低重复寻源成本。

#### 3.3.2 具体措施

1. 供应商分类分层
   按物料类别、工艺能力、区域、认证状态、战略等级、风险等级、合作状态等维度对供应商分类。

2. 资源可见与权限控制
   在权限允许范围内，实现跨产业、跨基地、跨部门的资源可见，支持业务单元快速检索集团已有供应商。

3. 资源调用机制
   建立供应商资源调用流程，记录资源调用方、使用场景、效果反馈和后续合作结果。

4. 供应商准入与退出
   建立统一准入认证流程，对供应商资质、质量体系、产能、成本、风险进行评估；对不合格或高风险供应商建立整改、降级和退出机制。

5. 资源复用评价
   统计资源复用次数、跨基地共享率、重复寻源减少量、采购周期缩短情况等指标，衡量资源池价值。

### 3.4 柔性供应池需求

#### 3.4.1 建设目标

针对关键物料和高风险供应环节建立备用供应商梯队，在风险发生时快速切换供应资源，提升供应链韧性。

#### 3.4.2 具体措施

1. 识别关键物料
   根据采购金额、生产影响、供应集中度、替代难度、质量要求、交期敏感度等因素识别关键物料。

2. 建立替代供应商清单
   为关键物料配置主供应商、备选供应商、潜在供应商和应急供应商，形成多层级替代梯队。

3. 建立能力匹配模型
   从工艺能力、产能规模、质量水平、交付能力、区域位置、成本结构、认证状态等维度判断替代供应商是否可用。

4. 建立动态激活规则
   当发生断供风险、价格异常、质量异常、地缘政治风险、交付延期、需求突增等事件时，系统自动推荐可激活供应商。

5. 定期演练和复盘
   对关键物料定期开展替代供应演练，验证切换周期、质量稳定性、成本影响和业务协同效率。

### 3.5 资源开发平台需求

#### 3.5.1 建设目标

将传统寻源从依赖人工调研的“体力活”，升级为由数据和 AI 支撑的“技术活”，提升寻源效率和资源匹配质量。

#### 3.5.2 具体措施

1. 支持产品与物料信息输入
   支持读取物料规格书、BOM、材质、性能指标、质量标准、技术参数等信息。

2. 支持产品结构和工艺解析
   自动提取产品关键特征，识别核心生产工序、工艺难点和能力要求。

3. 建立产业集群地图
   根据物料类别、工艺能力、成本优势、技术优势、区域风险等维度，定位全球或区域范围内的优势产业集群。

4. 智能推荐潜在供应商
   结合供应商画像、行业数据、外部资源和历史绩效，推荐高匹配度供应商列表。

5. 输出智能寻源报告
   报告应包括推荐供应商列表、匹配理由、初步成本区间、质量与交付能力、供应链稳定性、地缘风险和合规风险分析。

### 3.6 数据治理平台需求

#### 3.6.1 建设目标

保障 SCROS 数据准确、完整、及时、一致，使上层模型、平台和 Agent 具备可靠的数据基础。

#### 3.6.2 具体措施

1. 建立数据标准体系
   包括编码标准、字段标准、口径标准、数据质量标准、数据接口标准和数据安全标准。

2. 建立主数据管理机制
   对供应商、物料、品类、组织、工艺、合同等核心主数据进行统一管理。

3. 建立数据清洗规则
   对重复数据、缺失数据、异常值、格式错误、口径不一致等问题自动识别和处理。

4. 建立数据质量看板
   展示数据完整性、准确性、及时性、一致性、问题处理进度等指标。

5. 建立数据责任机制
   明确各类数据的业务责任部门、数据管理员、审批人和更新周期。

### 3.7 智能决策平台需求

#### 3.7.1 建设目标

将 AI 算法、大数据分析和业务规则引入供应链关键决策流程，为采购策略、供应商份额、成本核价、风险预警、资源调度提供科学建议。

#### 3.7.2 具体措施

1. 建立统一评分模型
   从价格、质量、交付、风险、产能、技术能力、战略协同等维度对供应商进行综合评分。

2. 建立核价模型
   结合历史采购价格、原材料行情、工艺路线、BOM、人工成本、制造费用和市场报价，形成合理成本区间和异常报价识别能力。

3. 建立份额分配模型
   根据供应商综合评分和业务规则，自动推荐采购份额比例，并支持采购经理在授权阈值内调整。

4. 建立风险预警模型
   对单一来源、财务风险、经营异常、地缘政治、战争疫情、关键原材料等风险进行监控、评分和预警。

5. 建立决策可解释机制
   所有模型建议需要说明关键依据、数据来源、权重、风险提示和人工干预记录，保证决策可追溯。

6. 建立结果回写机制
   将采购执行结果、供应商表现、成本节约、风险处置结果回写资源湖，持续优化模型。

### 3.8 供应商 360 度画像需求

#### 3.8.1 建设目标

为供应商准入选择、全周期绩效评估、采购份额动态分配和风险实时监控提供全面、客观、精准的数据决策支持。

#### 3.8.2 画像维度

1. 能力画像：核心基石
   评估技术研发能力、产能供给规模、设备能力、扩产能力和成本结构合理性。

2. 成本画像：竞争优势
   分析产品价格水平、全生命周期成本竞争力、价格稳定性和降本潜力。

3. 质量画像：品质保障
   评估质量绩效、质量体系、来料合格率、异常处理能力和售后质量表现。

4. 交付画像：履约核心
   评估准时交付率、订单完成率、交付周期、响应速度和服务能力。

5. 风险画像：安全屏障
   评估财务稳健性、运营可持续性、合规经营风险、法律诉讼风险和舆情风险。

6. 战略协同画像：长期共赢
   评估历史合作表现、战略契合度、协同意愿、创新能力和长期合作价值。

#### 3.8.3 输出要求

1. 输出供应商综合评分和分项评分。
2. 输出供应商优势、短板、风险和改进建议。
3. 支持按品类、基地、产业、区域、风险等级筛选供应商。
4. 支持画像自动更新和历史趋势对比。
5. 支持画像结果被份额模型、风险模型、寻源 Agent 调用。

### 3.9 风险管理体系需求

#### 3.9.1 建设目标

建立覆盖风险识别、风险评估、风险应对、监控审查的闭环管理体系，实现风险前置预警和快速处置。

#### 3.9.2 风险管理流程

1. 风险识别
   通过内部数据、第三方征信、舆情信息、市场行情、政策信息、全球风险情报等渠道自动识别风险。

2. 风险评估
   对风险发生概率、影响程度、影响范围、紧急程度和可替代性进行量化评分。

3. 风险应对
   根据风险等级自动推荐应对策略，包括供应商整改、份额调整、启动备选供应商、提前备货、价格锁定、合同调整等。

4. 监控审查
   对风险处置结果进行跟踪和复盘，优化风险规则和应急预案。

#### 3.9.3 重点风险类型

1. 单一来源风险
   自动识别采购额占比过高、供应商集中度过高的物料，避免对单一供应商过度依赖。

2. 供应商财务风险
   对接第三方征信数据，监控偿债能力、负债率、经营异常、司法诉讼等指标。

3. 地缘政治风险
   动态追踪贸易政策、关税壁垒、地区稳定性和国际关系变化。

4. 战争与疫情风险
   对突发公共卫生事件、地区武装冲突、物流封锁等不可抗力因素进行即时响应。

5. 关键原材料风险
   监控大宗商品价格波动、关键原材料供应中断和市场供需变化。

### 3.10 动态份额模型需求

#### 3.10.1 建设目标

引入市场化竞争机制，通过客观评分和动态调整，让优质供应商获得更多业务机会，同时推动采购成本优化和供应商绩效提升。

#### 3.10.2 计算逻辑

动态份额模型应基于综合评分进行份额推荐。综合评分可采用以下逻辑：

```text
综合评分 = 价格得分 * 权重 + 质量得分 * 权重 + 交付得分 * 权重 + 风险得分 * 权重 + 产能得分 * 权重 + 战略协同得分 * 权重
```

不同品类、不同物料可配置不同权重。对于关键物料，应提高质量、交付和风险权重；对于通用品类，可适当提高价格和交付权重。

#### 3.10.3 具体措施

1. 自动推荐份额
   系统基于供应商综合评分，自动推荐合格供应商采购份额比例，例如 6:3:1。

2. 定期动态重算
   每季度根据最新价格、质量、交付、风险、产能等数据重新计算份额。

3. 支持人工阈值内调整
   采购经理可在授权阈值内调整份额，但需填写原因，并保留审批和审计记录。

4. 建立公平透明机制
   以客观数据为主要依据，减少主观偏好，增强供应商信任。

5. 建立正向激励机制
   绩效优秀、风险较低、成本有优势的供应商获得更多业务；绩效下降或风险升高的供应商份额相应下降。

### 3.11 六大 AI Agent 需求

#### 3.11.1 寻源 Agent

目标：让优质资源主动浮现，将传统数周级寻源调研压缩至小时级。

输入：

1. 产品结构、物料规格书、BOM。
2. 材质、性能指标、质量标准。
3. 工艺要求、技术参数、采购需求。

处理：

1. 自动识别产品关键特征。
2. 自动解析工艺路线和核心生产难点。
3. 匹配产业集群和优势供应区域。
4. 基于画像算法筛选高匹配度供应商。

输出：

1. 高匹配度供应商推荐列表。
2. 供应商匹配理由。
3. 初步成本区间估算。
4. 供应链稳定性、地缘风险和合规风险评估报告。

#### 3.11.2 核价 Agent

目标：提升采购核价效率和价格判断准确性，识别价格虚高和异常报价。

输入：

1. BOM、工艺路线、物料规格。
2. 历史采购价格和询报价记录。
3. 原材料市场价格和行业行情。
4. 供应商成本结构、产能和区域信息。

处理：

1. 构建材料、工艺、人工、制造费用、物流等成本拆分。
2. 对比历史价格曲线和市场行情。
3. 判断报价合理区间和异常波动。
4. 生成谈判参考和降本空间建议。

输出：

1. 合理成本区间。
2. 报价异常提示。
3. 价格趋势分析。
4. 谈判策略和降本建议。

#### 3.11.3 画像 Agent

目标：自动生成和更新供应商 360 度画像，支撑准入、绩效、份额和风险决策。

输入：

1. 供应商基础信息。
2. 价格、质量、交付、产能、风险、合作历史数据。
3. 外部征信、舆情、政策和行业数据。

处理：

1. 自动采集和清洗供应商数据。
2. 生成六大画像维度评分。
3. 识别供应商优势、短板和风险标签。
4. 形成供应商历史趋势。

输出：

1. 供应商综合画像。
2. 分项评分和风险标签。
3. 绩效趋势报告。
4. 供应商改进建议。

#### 3.11.4 份额 Agent

目标：作为动态份额模型的“操盘手”，将采购策略制定从经验驱动升级为 AI 和数据驱动。

输入：

1. 供应商画像全景数据。
2. 企业采购需求计划。
3. 份额分配规则和业务约束。
4. 风险、产能、价格和交付数据。

处理：

1. 调用动态份额模型计算综合评分。
2. 使用优化算法生成最优份额分配方案。
3. 评估成本节约、供应风险和执行可行性。

输出：

1. 供应商份额推荐。
2. 采购计划建议。
3. 预期成本节约分析。
4. 风险评估和调整建议。

#### 3.11.5 风险 Agent

目标：实现供应链风险的实时监控、智能预警和应急方案推荐。

输入：

1. 供应商财务、法律、合规、舆情数据。
2. 采购集中度和单一来源数据。
3. 地缘政治、贸易政策、战争疫情、市场行情数据。
4. 关键原材料供需和价格波动数据。

处理：

1. 自动识别风险事件和风险趋势。
2. 计算风险等级和影响范围。
3. 匹配柔性供应池中的替代方案。
4. 生成风险处置建议。

输出：

1. 风险预警通知。
2. 风险等级和原因说明。
3. 替代供应商推荐。
4. 应急处置方案和跟踪清单。

#### 3.11.6 调度 Agent

目标：提升供应链响应速度，支持产能、订单、供应商资源和柔性供应池的动态调度。

输入：

1. 订单需求和采购计划。
2. 供应商产能、交付周期和库存信息。
3. 柔性供应池可用资源。
4. 生产基地需求和供应约束。

处理：

1. 分析供需缺口和产能瓶颈。
2. 推荐资源切换和供应商调度方案。
3. 支持跨地域、跨基地的资源协同。
4. 评估调度方案对成本、交期和风险的影响。

输出：

1. 供应调度建议。
2. 产能预警和资源缺口提示。
3. 柔性供应激活建议。
4. 调度执行跟踪和效果复盘。

### 3.12 供应链生态协同需求

#### 3.12.1 建设目标

向核心战略供应商开放部分非敏感数据和协同功能，构建数据共享、风险共担、流程互通的供应链生态。

#### 3.12.2 具体措施

1. 建立供应商协同门户
   支持供应商查看协同事项、质量整改、交付计划、风险提示、绩效反馈等信息。

2. 开放非敏感协同数据
   在权限和合规边界内，向核心供应商开放预测、交付、质量、整改、绩效等必要信息。

3. 建立协同流程
   支持供应商准入、资质维护、质量整改、交付协同、风险响应、绩效改进等流程线上化。

4. 建立共担机制
   针对供应风险、质量异常、交付异常等问题，形成集团与供应商共同响应、共同改进的机制。

5. AI 算法组
   负责人：AI 部门算法专家。
   职责：主导核心 AI 算法研发、训练和优化，为智能决策和业务场景提供技术支撑。

6. 运营调度组
   负责人：供应链计划部门负责人。
   职责：实时监控产能状态，推动柔性调度体系落地，提升供应链响应速度。

## 4. 商业模式

### 4.1 商业模式定位

SCROS 项目本质上是集团内部供应链能力平台和价值创造系统。其近期商业模式不是对外销售软件，而是通过“平台建设 + 数据资产 + 智能决策 + 供应商生态协同”的方式，在集团内部形成降本、增效、保供、控险和组织能力沉淀的价值闭环。

可以概括为：

```text
集团建设平台 -> 汇聚供应链资源 -> 业务单元调用能力 -> 数据和模型辅助决策 -> 供应商按绩效竞争 -> 集团获得降本增效和供应链韧性
```

### 4.2 运行机制

#### 4.2.1 集团统一建设，业务单元共享调用

集团层面统一建设 SCROS 平台，供应链采购部、IT 部门、AI 部门、计划部门共同运营。各产业、基地和业务单元通过平台调用供应商资源、寻源能力、核价能力、画像能力、风险预警和调度能力。

运行逻辑：

1. 集团统一沉淀供应商资源和数据。
2. 各业务单元按权限共享和复用资源。
3. 平台按业务场景提供标准化能力。
4. 业务执行结果回写资源湖。
5. 数据持续积累，模型持续优化。

#### 4.2.2 供应商进入资源池，按绩效获得机会

供应商通过统一准入认证进入资源池。系统持续采集其价格、质量、交付、风险、产能和协同表现，并形成 360 度画像。

运行逻辑：

1. 供应商准入后进入资源池。
2. 关键物料供应商进入柔性供应池候选范围。
3. 系统基于绩效和风险动态评分。
4. 份额 Agent 根据评分推荐业务份额。
5. 优质供应商获得更多订单机会。
6. 高风险或低绩效供应商被整改、降级或退出。

这种机制把供应商管理从静态名录管理，升级为动态竞争和持续优化。

#### 4.2.3 以动态份额模型引入市场化竞争

SCROS 通过动态份额模型，将供应商的价格、质量、交付、风险、产能和战略协同表现转化为业务份额建议。

运行逻辑：

1. 供应商表现越好，综合评分越高。
2. 综合评分越高，获得的推荐份额越高。
3. 供应商为获得更多业务，会持续改善质量、交付、成本和协同。
4. 集团通过良性竞争获得更低成本、更高质量和更稳定供应。

#### 4.2.4 以柔性供应池形成供应链保险机制

柔性供应池承担供应链“备胎”和“保险”角色。当主供应商出现异常时，系统可以快速推荐替代供应商，减少停线、断供和交付延误风险。

运行逻辑：

1. 对关键物料预先建立替代梯队。
2. 持续评估替代供应商能力。
3. 风险触发时自动推荐替代方案。
4. 业务部门确认后快速切换资源。
5. 处置结果回写系统，优化后续规则。

#### 4.2.5 以供应商生态协同提升长期竞争力

当 SCROS 能力成熟后，可向核心战略供应商开放部分非敏感数据和协同功能，实现需求、交付、质量、风险和绩效的协同管理。

运行逻辑：

1. 集团与核心供应商共享必要协同信息。
2. 供应商提前感知需求变化和质量要求。
3. 双方共同处理风险和异常。
4. 供应商参与持续改进和创新协同。
5. 集团形成更稳定、更高效、更有韧性的供应链生态。

### 4.3 价值创造方式

SCROS 的商业价值主要来自以下方面：

1. 降低采购成本
   通过智能核价、资源共享、动态份额和市场化竞争，降低采购价格和综合采购成本。

2. 降低库存成本
   通过供应链协同、产能可视、柔性调度和风险预警，减少过度备货和库存占用。

3. 提升采购人效
   通过 AI 寻源、自动画像、自动核价、自动绩效评估和智能报告，减少人工调研、数据整理和重复沟通。

4. 降低供应风险损失
   通过风险预警、柔性供应池和替代方案推荐，减少断供、质量异常、价格暴涨、交付延迟带来的损失。

5. 提升管理透明度
   通过统一数据和审计追溯，使供应商选择、价格判断、份额分配和风险处置更加透明。

6. 沉淀组织能力
   将采购经验、供应商评估方法、核价规则和风险处置策略固化为平台能力，减少对个人经验的依赖。

### 4.4 成本投入构成

项目建设需要投入以下成本：

1. 平台建设成本
   包括资源湖、三大平台、AI Agent、协同门户、权限体系、接口集成等研发成本。

2. 数据治理成本
   包括历史数据清洗、主数据建设、数据标准制定、数据质量监控和数据责任机制建设。

3. 外部数据成本
   包括征信数据、风险情报、行业数据、市场价格数据、海外资源数据等采购成本。

4. AI 模型建设成本
   包括算法研发、模型训练、提示词工程、模型评估、模型治理、算力和服务调用成本。

5. 组织变革成本
   包括流程调整、人员培训、供应商协同、试点推广和业务运营成本。

6. 运营维护成本
   包括系统运维、数据维护、模型迭代、供应商管理和持续优化成本。

### 4.5 收益衡量方式

建议建立项目收益台账，从以下指标衡量商业回报：

1. 成本类指标
   采购成本节约金额、采购成本节约率、核价节约金额、异常报价识别金额。

2. 效率类指标
   寻源周期缩短率、采购周期缩短率、重复寻源减少次数、自动化报告生成率。

3. 资源类指标
   供应商主数据入库率、资源共享率、资源调用次数、跨基地资源复用率。

4. 风险类指标
   单一来源风险下降率、风险预警准确率、风险处置闭环率、替代供应商覆盖率。

5. 绩效类指标
   准时交付率、质量合格率、供应商绩效提升率、绩效评估自动化率。

6. 生态类指标
   核心供应商协同覆盖率、供应商整改闭环率、战略供应商满意度、协同流程线上化率。

### 4.6 远期商业延展方向

在集团内部价值闭环成熟后，SCROS 可进一步探索以下延展方向，但需结合数据安全、商业机密和合规要求进行专项评估：

1. 供应链能力中台化
   将寻源、核价、画像、份额、风险和调度能力封装为标准服务 API，供集团更多业务系统调用。

2. 战略供应商协同平台化
   与核心供应商共同建设计划协同、质量协同、风险协同和创新协同机制。

3. 行业资源和数据服务能力
   在合规前提下，沉淀产业地图、供应商评估方法、成本模型和风险模型，形成可复用的方法论资产。

4. 全球供应网络运营能力
   面向海外供应商、海外基地和跨区域生产协同，形成全球供应资源开发和调度能力。

## 5. 总结

海天集团供应链资源湖（SCROS）项目的核心价值，是将分散的供应商资源和供应链数据转化为集团级数据资产，再通过资源池、柔性供应池、三大平台和六大 AI Agent，将数据资产转化为可执行、可复用、可优化的业务能力。

项目建成后，海天供应链将从传统的经验驱动、分散管理、事后响应，升级为数据驱动、集团统筹、智能决策和生态协同的新模式。其最终目标是打造一个 AI 深度驱动、具备强大韧性和协同能力的供应链资源操作系统，连接优质资源，赋能业务增长，为集团可持续发展构建核心技术底座与生态护城河。
