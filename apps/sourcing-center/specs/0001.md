# 海天塑机 SRM 项目痛点与 SCROS 资源湖方案价值说明

## 1. 文档目的

本文基于 `assets/海天塑机_SRM项目总结分享(2).pptx` 的项目总结内容，提炼海天塑机 SRM 项目背后反映出的采购与供应链管理痛点，并说明我们新的“海天集团供应链资源湖 SCROS”方案如何进一步解决这些痛点。

PPT 本身主要是 SRM 项目总结，未直接以“痛点清单”形式呈现。因此本文的痛点提炼，是基于 PPT 中的项目背景、业务架构、系统实现模块、业务要点和应用效果进行归纳。

## 2. 一句话结论

海天现有 SRM 已经完成了采购业务从线下到线上的关键跨越，解决了流程电子化、订单协同、供应商管理和结算协同等问题；但从 PPT 内容看，系统能力仍主要集中在“业务流程执行”和“过程协同”层面。

下一阶段真正要解决的，是集团供应链资源如何统一、如何复用、如何智能决策、如何提前预警、如何形成柔性供应能力的问题。SCROS 资源湖的价值，就是在 SRM 已有流程基础上，向上建设集团级供应链资源操作系统。

## 3. PPT 反映出的核心痛点

### 3.1 供应商资源已经在线化，但集团级资源统筹仍不足

PPT 中 SRM 已经覆盖供应商注册、认证、合格供应商管理、绩效评估、退出和黑名单等生命周期流程，也提出了“集团供应商共享平台”“合格供应商库”“供应商资源池”等概念。

这说明海天已经意识到供应商资源不能只停留在单产业、单基地、单采购员手中。但从现有 SRM 项目定位看，系统更多是在支持供应商流程管理，并不等同于已经形成集团级资源运营能力。

痛点表现：

- 各产业、基地、业务单元的供应商资源仍可能存在割裂。
- 同类物料、相似工艺、相似供应商能力无法被充分复用。
- 供应商信息有记录，但不一定能快速转化为“可查、可调、可推荐、可替代”的集团资源。
- 资源池存在设计，但更偏静态维护，缺少动态能力匹配和智能推荐。

SCROS 解决方式：

- 建设统一供应链资源湖，为供应商建立唯一 ID 和集团统一视图。
- 建设统筹资源池，把合格供应商从“流程结果”升级为“集团供应商超市”。
- 通过物料类别、工艺能力、区域、认证状态、战略等级、风险等级等维度进行资源分类分层。
- 支持跨产业、跨基地、跨部门查询、调用、复用和反馈沉淀。

### 3.2 供应商全生命周期流程已建立，但数据治理和画像能力仍不够

PPT 中供应商认证生命周期包括注册、潜在供应商池、认证、样品认证、资质审核、合格供应商、绩效评估、整改、冻结、淘汰、黑名单等环节。

这套流程很完整，但流程完整不代表决策质量稳定。供应商是否值得引入、是否应增加份额、是否需要降级或退出，本质上依赖数据质量和画像模型。

痛点表现：

- 供应商信息、资质、绩效、质量、交付、风险等数据来源多，口径容易不一致。
- 对供应商的判断可能仍依赖采购员经验、评审小组主观判断和历史印象。
- 供应商分类分级、准入、退出、整改缺少统一可解释模型。
- 供应商数据存在，但没有充分沉淀为动态 360 度画像。

SCROS 解决方式：

- 建设数据治理平台，统一编码、字段、口径、质量、接口和安全标准。
- 建设供应商 360 度画像，覆盖能力、成本、质量、交付、风险、战略协同等维度。
- 将 SRM 中的注册、认证、绩效、质量、订单、财务等数据沉淀为画像资产。
- 用画像 Agent 自动更新供应商标签、评分、优势短板和改进建议。

### 3.3 寻源、询报价、招投标和竞价流程在线化，但“找谁、为什么找、怎么优选”仍有提升空间

PPT 中 S02 覆盖询报价、招投标、竞价、定价、份额审核、SAP 货源清单和价格信息记录同步等能力。该模块解决了商务过程透明、报价过程在线、历史价格辅助核价、结果可追溯等问题。

但采购管理的更高价值不只在“把询价流程搬到线上”，而在于系统能否主动推荐供应商、判断报价合理性、识别异常报价、形成谈判策略。

痛点表现：

- 寻源仍可能依赖采购员经验和已有供应商名单。
- 同类物料重复询价、重复开发供应商，效率和议价能力受限。
- 历史价格可以辅助核价，但未必能结合 BOM、工艺路线、原材料行情形成动态核价模型。
- 竞价结果能落入 SAP，但对后续资源复用、成本规律、供应商能力沉淀不足。

SCROS 解决方式：

- 资源开发平台通过规格书、BOM、材质、质量标准、工艺参数自动解析能力要求。
- 寻源 Agent 结合产业集群地图、供应商画像、历史绩效和外部资源，推荐高匹配供应商。
- 核价 Agent 结合历史价格、原材料行情、工艺路线、BOM、市场报价，识别异常报价和合理成本区间。
- 智能决策平台输出可解释的推荐理由、成本区间、风险提示和谈判建议。

### 3.4 采购履行协同已经覆盖订单、交货、VMI 和委外，但供应链柔性调度能力仍不足

PPT 中 S03 覆盖采购订单确认、交期回复、ASN、交货单、条码标签、预测协同、VMI 库存、产能提报、委外订单等内容。应用效果中也提到系统产生大量送货单，并有多家供应商参与。

这说明 SRM 已经有效支撑了订单履行协同。但订单履行侧更偏执行协同，面对断供、延期、产能不足、需求突增时，需要更强的替代资源和动态调度能力。

痛点表现：

- 供应商交期、产能、库存和预测信息已在线，但未必能自动形成供需缺口判断。
- 关键物料发生风险时，备选供应商梯队和切换方案不一定清晰。
- VMI 和委外协同解决库存与执行问题，但对柔性供应池建设支撑不足。
- 跨基地、跨区域、跨供应商资源切换仍可能依赖人工协调。

SCROS 解决方式：

- 建设柔性供应池，为关键物料建立主供、备选、潜在、应急供应商梯队。
- 调度 Agent 基于订单需求、采购计划、供应商产能、交付周期、库存信息进行供需缺口分析。
- 风险触发时，系统自动匹配替代供应商，评估成本、交期、质量和风险影响。
- 支持替代供应演练、切换周期验证、质量稳定性验证和复盘沉淀。

### 3.5 绩效和风险管理已有模型，但预警能力和结果应用仍可进一步升级

PPT 中 S04 建立供应商绩效模型，覆盖质量、成本、交付、响应、技术、环境、社会责任等维度，并支持供应商整改、定级、冻结、淘汰等结果应用。同时也包含供应商风险评估流程和等级划分。

这说明海天已经有绩效和风险管理意识。但传统绩效风险模块通常存在数据滞后、评估周期长、结果偏事后、对突发外部风险覆盖不足的问题。

痛点表现：

- 绩效评估可能以月度或阶段性结果为主，实时预警不足。
- 风险评估更多覆盖供应商自身能力和经营表现，对财务、合规、舆情、地缘、原材料波动等外部风险联动不足。
- 绩效结果能用于整改、冻结、淘汰，但对份额动态调整、备选激活、风险处置建议支持不足。
- 风险管理缺少从识别、评估、应对、监控审查到结果回写的闭环。

SCROS 解决方式：

- 风险 Agent 实时监控财务、法律、合规、舆情、地缘政治、关键原材料等风险。
- 建立风险识别、评估、应对、监控审查闭环。
- 将风险标签纳入供应商画像、份额模型和柔性供应池激活规则。
- 输出风险等级、原因说明、替代供应商推荐和应急处置方案。

### 3.6 质量整改和扣款流程已经线上化，但质量问题与供应商能力提升之间还需更强闭环

PPT 中 S05 覆盖质量通知、质量整改、整改报告审批、整改稽核、质量索赔、财务扣款等场景，并强调质量问题响应时效、严重程度与绩效评估关联，长期改进无效可触发退出、财务冻结、采购订单冻结。

这说明质量协同已纳入 SRM，但质量数据的价值不仅在于流程闭环，更在于沉淀为供应商能力画像和风险预警依据。

痛点表现：

- 质量问题流程能闭环，但质量趋势、问题根因、供应商能力变化不一定被持续建模。
- 质量数据、绩效数据、份额数据、风险数据之间联动不足。
- 对质量长期波动供应商，系统可能能处罚，但未必能提前推荐替代资源。

SCROS 解决方式：

- 将 QMS、SRM、采购履行和绩效数据统一沉淀到质量数据库和供应商画像。
- 画像 Agent 识别质量趋势、短板和整改效果。
- 风险 Agent 对质量异常、交付异常触发预警。
- 调度 Agent 联动柔性供应池，推荐可替代供应商和切换方案。

### 3.7 品类资源池已有设计，但距离“战略资源运营”还有差距

PPT 中 S06 提到采购早期介入、动态物料模型、品类资源池、品类采购策略、供应商健康运营及风险预警，并明确品类资源池可关联供应商、价格、份额和采购策略。

这是非常关键的基础能力，但仍需要进一步从“品类维护”升级为“品类资源运营”。

痛点表现：

- 品类资源池依赖物料、供应商、价格、份额等数据维护质量。
- 品类策略可能仍由人工维护，缺少 AI 辅助识别战略型、杠杆型、瓶颈型、一般型物料。
- 研发早期介入需要快速识别可用资源、工艺能力和风险，但传统 SRM 响应速度有限。
- 资源池本身未必能形成集团级复用和动态推荐。

SCROS 解决方式：

- 资源开发平台支持产品结构、工艺路线和物料特征解析。
- 产业集群地图沉淀不同品类、工艺、区域、成本和风险能力。
- 份额 Agent 基于综合评分、业务约束、产能、风险、价格、交付数据推荐份额分配。
- 统筹资源池推动品类资源跨基地、跨产业复用。

### 3.8 合同、财务结算已实现协同，但对采购价值创造的支撑还可以更强

PPT 中 S07 和 S08 覆盖合同模板、合同拟制、签署、履约、归档、电子签章、财务共享、对账、开票、SAP 过账、金税验真等能力。

这些能力让采购履约和结算更规范，但对管理层来说，更关心的是成本节约、履约风险、供应商贡献和资金占用优化。

痛点表现：

- 合同和财务数据已记录，但不一定充分进入供应商画像和成本分析。
- 对账、开票、付款过程可协同，但对长期价格趋势、合同履约风险、供应商价值贡献分析不足。
- 采购成本、质量成本、库存成本和风险损失之间缺少统一价值视图。

SCROS 解决方式：

- 将合同价格、发票、扣款、付款、履约数据沉淀到价格与财务相关数据资产。
- 核价 Agent 和智能决策平台用于识别价格异常、成本节约空间和谈判策略。
- 供应商画像纳入成本画像、全生命周期成本、价格稳定性和降本潜力。
- 管理层可从单笔执行结果上升到供应商长期价值评估。

## 4. SRM 与 SCROS 的关系

SCROS 不是要否定或替代 SRM，而是在 SRM 已经完成流程在线化、供应商协同、订单履行和财务结算的基础上，向上建设“资源、数据、模型、智能决策”能力。

可以这样理解：

| 层级 | SRM 已解决的问题 | SCROS 进一步解决的问题 |
| --- | --- | --- |
| 流程 | 注册、认证、询报价、订单、送货、合同、结算线上化 | 流程结果沉淀为可复用数据资产 |
| 协同 | 采购方、供应商、财务、质量、仓储在线协同 | 跨产业、跨基地、跨部门资源协同 |
| 管控 | 审批、权限、状态、绩效、风险、黑名单 | 模型化评分、动态份额、风险预警、柔性替代 |
| 数据 | 业务过程数据记录 | 统一资源湖、数据治理、供应商 360 画像 |
| 决策 | 人工基于系统数据判断 | AI Agent 辅助寻源、核价、份额、风险、调度 |
| 价值 | 提升流程效率、减少错误、增强透明度 | 降低成本、减少重复寻源、增强供应链韧性、沉淀组织能力 |

## 5. 方案价值总结

### 5.1 对采购效率

通过资源开发平台和寻源 Agent，将规格书、BOM、工艺要求转化为供应商推荐和智能寻源报告，减少人工调研和重复沟通。

### 5.2 对采购成本

通过核价 Agent、动态份额模型、历史价格曲线、原材料行情和竞价/询价数据联动，识别价格虚高和异常报价，支持谈判与降本。

### 5.3 对供应商管理

通过供应商 360 度画像，将供应商注册、认证、质量、交付、成本、风险、合同、财务等数据统一沉淀，形成可解释、可追溯的供应商评估体系。

### 5.4 对风险管理

通过风险 Agent 和柔性供应池，实现风险识别、风险评估、替代推荐、处置跟踪和结果回写，减少断供、延期、质量异常、价格波动带来的冲击。

### 5.5 对集团资源协同

通过统筹资源池，把不同产业、基地和部门沉淀的供应商资源转化为集团可共享、可调用、可评价的资源超市，减少重复寻源和重复认证。

### 5.6 对管理层决策

通过智能决策平台，把采购经验、核价规则、份额策略、风险判断和供应商评估逻辑沉淀为模型，让决策从“经验判断”升级为“数据 + 模型 + 人工确认”的闭环。

## 6. 对外沟通时的核心表达

建议不要把 SCROS 表达为“再做一个 SRM”，而应表达为：

> 海天的 SRM 已经把采购流程搬到了线上，SCROS 要做的是把线上流程沉淀下来的供应商、价格、质量、交付、产能、风险、工艺和行业数据，变成集团可复用的资源、可计算的模型、可预警的风险和可执行的智能决策。

更简洁的说法：

> SRM 解决的是采购流程怎么跑，SCROS 解决的是供应链资源怎么选、怎么用、怎么优、怎么防风险。
